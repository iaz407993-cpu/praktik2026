# Архітектура «Панорама-ОВУ»

```text
┌────────────┐   SQL (psycopg2,     ┌──────────────────┐   HTTP/JSON    ┌──────────────────────────┐
│ PostgreSQL │◄── raw, autocommit) ─│ FastAPI (sync)   │◄──── fetch ────│ Web: index.html + app.js │
│ incidents  │                      │ api/main.py      │   CORS: *      │ Chart.js (CDN)           │
└────────────┘                      └──────────────────┘                └──────────────────────────┘
   db/schema.sql, db/seed.py           api/db.py: get_conn()               ?view=executive|analyst|demo
```

## Дані
Одна таблиця `incidents(id, occurred_at, sector, direction, event_type, intensity 1..50, source, summary)` з індексами на `occurred_at`, `sector`, `direction`, `event_type`. `db/seed.py` генерує 500 записів за 90 днів (5 секторів, 6 напрямків, 5 типів) з `random.seed(42)` і закладеними закономірностями: частота подій зростає до кінця періоду, «Східний» напрямок посилюється в останні 3 тижні — щоб дашборд мав що «виявляти».

## Фільтрація
Клас `Filters` (FastAPI `Depends`) формує умову `WHERE` з параметрами — спільну для всіх аналітичних ендпоїнтів. Метод `where(from, to)` дозволяє підставити інший період з тими самими фільтрами — на цьому побудоване порівняння періодів.

## Порівняння «цей період vs попередній»
Попередній період — інтервал **такої самої тривалості**, що безпосередньо передує поточному (наприклад, 06.10–04.11 → 06.09–05.10). Без `from/to` API бере останні 30 днів даних; web за замовчуванням ставить саме цей період, тож KPI і Δ% завжди узгоджені. Δ% = (поточне − попереднє) / попереднє × 100; якщо попереднє = 0 → `null` («н/д»).

## Режими аудиторій
| Режим | Показано | Приховано | Чутливі поля |
|---|---|---|---|
| executive | KPI + Δ%, тренд, інсайт | розподіли, панорама, heatmap, таблиця | — |
| analyst | усе | — | показуються |
| demo / public | KPI, тренд, інсайт, розподіли, панорама, heatmap | таблиця інцидентів | `source` не запитується (`public=true`) і не відображається |

Приховування в demo реалізоване **на рівні API** (`public=true` прибирає `source` з відповіді), а не лише CSS — у браузер чутливі дані не потрапляють.

## Узгоджене оновлення
`apply()` в `app.js` за один прохід паралельно запитує KPI, порівняння, панораму, тренди (поточний і попередній) і лише видимі в поточному режимі блоки; застарілі відповіді (якщо користувач змінив фільтр до завершення запиту) відкидаються лічильником `seq`. Фільтри та режим зберігаються в URL.

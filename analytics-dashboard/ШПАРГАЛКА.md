## ⚡ Швидкий старт (усе вже встановлено)

```powershell
cd C:\Users\User\analytics-dashboard
powershell -ExecutionPolicy Bypass -File .\start.ps1   # БД + бекенд + фронтенд + браузер
powershell -ExecutionPolicy Bypass -File .\stop.ps1    # зупинити PostgreSQL
```

Встановлено: портативний **PostgreSQL 17.11** у `C:\Users\User\pgsql` (дані — `C:\Users\User\pgsql-data`,
користувач `postgres`, пароль `postgres`, порт 5432). Це **не служба Windows** — після перезавантаження
ПК запускайте `start.ps1` (або `C:\Users\User\pgsql\bin\pg_ctl.exe -D C:\Users\User\pgsql-data start`).
psql: `C:\Users\User\pgsql\bin\psql.exe -U postgres -d analytics_db`

## 0. Один раз: встановити PostgreSQL (вже зроблено — див. вище)

1. Завантажте з https://www.postgresql.org/download/windows/ і встановіть.
2. Запам'ятайте пароль користувача `postgres`, порт залиште `5432`.
3. (Необов'язково) додайте `psql` у PATH на поточну сесію:
   ```powershell
   $env:Path += ";C:\Program Files\PostgreSQL\17\bin"   # 17 — ваша версія
   ```

## 1. БАЗА ДАНИХ — створити й заповнити

**Варіант А — через Python (psql не потрібен):**
```powershell
cd C:\Users\User\analytics-dashboard\backend
copy .env.example .env          # відкрийте .env і впишіть свій DB_PASSWORD
.\.venv\Scripts\Activate.ps1
python init_db.py
```

**Варіант Б — через psql:**
```powershell
cd C:\Users\User\analytics-dashboard\database
psql -U postgres -c "CREATE DATABASE analytics_db;"
psql -U postgres -d analytics_db -f 01_schema.sql
psql -U postgres -d analytics_db -f 02_seed.sql
```

**Варіант В — pgAdmin:** створіть БД `analytics_db` → Query Tool → відкрийте й виконайте `01_schema.sql`, потім `02_seed.sql`.

Перевірка: `psql -U postgres -d analytics_db -c "SELECT count(*) FROM units;"` → 70

## Часті проблеми

| Помилка | Рішення |
|---|---|
| `Activate.ps1 cannot be loaded… running scripts is disabled` | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (один раз) |
| `password authentication failed` | неправильний `DB_PASSWORD` у `backend\.env` |
| `Connection refused` / порт 5432 | не запущено службу: `Get-Service postgresql*` → `Start-Service postgresql-x64-17` |
| `database "analytics_db" does not exist` | виконайте крок 1 |
| На дашборді «API недоступний» | не запущено бекенд (крок 2) або інша адреса в `frontend\data\config.json` |
| Порт 8000 / 5500 зайнятий | `--port 8001` / `http.server 5501` і оновіть `apiBaseUrl` у config.json |
| Зупинити сервер | `Ctrl + C` у відповідному терміналі |

## API (коротко)

| Ендпоінт | Що повертає |
|---|---|
| `GET /api/units?affiliation=F&region_id=4&unit_type=armor` | підрозділи з SIDC і координатами |
| `GET /api/events?limit=25&days=30` | журнал подій |
| `GET /api/stats/summary` | KPI |
| `GET /api/stats/units-by-type` | свої / противник за типом |
| `GET /api/stats/events-timeline?days=30` | події по днях |
| `GET /api/stats/events-by-region` · `/events-by-type` · `/readiness` | розподіли для графіків |
| `GET /api/regions` · `/api/unit-types` | довідники |
| `GET /api/strike-types` · `/api/loss-categories` · `/api/meta/date-range` | види ураження, категорії втрат, межі дат |
| `GET /api/strikes?…&limit=100` | журнал уражень із втратами `{total, items}` |
| `GET /api/strikes.csv?…` | уся вибірка в CSV (для Excel) |
| `GET /api/stats/strikes-summary?…` | підсумки + порівняння з попереднім періодом |
| `GET /api/stats/strikes-timeline?…` | ураження й втрати по днях / тижнях |
| `GET /api/stats/strikes-by-type` · `/losses-by-category` · `/strikes-by-region` | розподіли |

| `GET /api/frontline?date=2026-10-31` | лінія розмежування, чинна на дату |
| `GET /api/supply-types` · `/api/depots` | види постачання (з нормами), склади |
| `GET /api/logistics/summary?…` | рейси, тонни, виконання плану, забезпеченість, вчасність, втрати + попер. період |
| `GET /api/logistics/timeline` · `/by-type` · `/by-status` · `/by-depot` | звіти логістики |
| `GET /api/logistics/units-coverage?…` | забезпеченість кожного підрозділу (від найнижчої) |
| `GET /api/logistics/deliveries?…&status=in_transit` · `/deliveries.csv` | журнал рейсів / CSV |

**Лінія розмежування** — таблиці `frontline_versions` (дата, з якої чинна) і `frontline_points`
(точки по порядку). Координати в `04_frontline.sql` **орієнтовні, навчальні** — для реальної
роботи додайте нову версію з офіційного джерела; дашборд сам покаже ту, що чинна на кінцеву дату вибірки.

**Логістика** — `05_logistics.sql`: `supply_types` (норма кг/особу/добу → потреба),
`depots`, `deliveries` (статуси: `delivered` вчасно, `delayed` запізнення > 2 год, `in_transit`, `lost`).
Забезпеченість = доставлено ÷ (чисельність × норма × днів періоду). Фільтр: `supply_type=ammo,fuel`.

**Фільтри вибірки** (однакові для уражень, втрат, логістики і подій):
`date_from=2026-10-01&date_to=2026-10-31&strike_type=fpv,artillery&region_id=4`
Коди видів ураження: `fpv` `drop_uav` `artillery` `mortar` `mlrs` `strike_uav` `atgm` `tank_fire` `aviation` `missile`.
Дані уражень: `database\03_strikes.sql` (заливається разом з усім через `python init_db.py`).
Вибірка зберігається в адресі сторінки (`#df=…&dt=…&st=…`), тож посилання можна надіслати колезі.

## Умовні знаки (SIDC, 15 символів)

`S F G P UCI--- - F ---` → схема · **приналежність** (F свій, H противник, N нейтр., U невід.) · земля · **статус** (P наявний, A плановий) · **функція** (UCI піхота, UCA танки, UCF артилерія, UCD ППО, UCR розвідка, UCVU БпЛА…) · **ешелон** (D взвод, E рота, F батальйон, H бригада).
SIDC генерується тригером у БД автоматично; новий підрозділ:
```sql
INSERT INTO units (name, unit_type, affiliation, echelon, region_id, lat, lon, personnel, readiness)
VALUES ('Новий підрозділ', 'armor', 'F', 'E', 10, 50.45, 30.52, 110, 90);
```
